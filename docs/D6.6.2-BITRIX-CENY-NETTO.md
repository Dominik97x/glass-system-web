# D6.6.2 — ceny netto w pozycjach Bitrix24

## Cel

Nowe Deale tworzone przez produkcyjny przepływ `database → Bitrix24` otrzymują cenę sprzedaży netto z FIX22, a nie cenę strony zawierającą VAT 8%.

Dla każdej pozycji wysyłane są:

```ts
price: cenaNetto
vatRate: BITRIX24_VAT_RATE
vatIncluded: "N"
```

W REST Bitrix24 pole nazywa się `taxIncluded`, dlatego faktyczny payload ma:

```ts
price: cenaNetto
taxRate: BITRIX24_VAT_RATE
taxIncluded: "N"
```

## Przykład 300 × 306 cm

- cena sprzedaży netto: `7 419,00 PLN`,
- VAT 8%: `593,52 PLN`,
- brutto w Bitrix24: `8 012,52 PLN`,
- orientacyjna cena strony pozostaje `8 013 PLN`.

Po zmianie VAT na 23% cena netto nadal wynosi `7 419,00 PLN`, a Bitrix24 wylicza `9 125,37 PLN` brutto.

## Zgodność wsteczna

Zmieniarka `bitrix:vat:*` obsługuje teraz:

- nowe pozycje netto z `TAX_INCLUDED=N` — zmienia tylko stawkę VAT,
- stare pozycje brutto z `TAX_INCLUDED=Y` — zachowuje netto i przelicza zapisane brutto,
- mieszany Deal — zachowuje netto każdej pozycji według jej modelu.

Wiersze z rabatem lub narzutem zapisanym bezpośrednio w pozycji nadal są blokowane przez zabezpieczenie D6.5.3.

## Weryfikacja lokalna

```powershell
npm run pricing:import

npm run bitrix:net-rows:verify
npm run lint
npm run build
```

## Test bezpieczny

Najpierw utworzyć nowy testowy Deal przez formularz kalkulatora. Nie migrować jeszcze istniejących Deali ani cen katalogowych.

Sprawdzić w zakładce Produkty:

- `Cena` jest ceną netto,
- `Podatek` wynosi 8%,
- `Podatek wliczony w` ma wartość `Nie`,
- `Suma podatku` i `Kwota` są naliczone przez Bitrix24.
